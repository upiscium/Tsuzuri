# Tsuzuri v0.2 Reliability Plan

## Goal

Make failures attributable and remove the current first-results bias before adding broader media support or sophisticated retrieval models.

## P0 implemented in this candidate

1. OpenAI-compatible LLM boundary
   - `/v1/chat/completions` is the serving contract.
   - JSON Schema, JSON-object, and prompt-only structured-output modes are capability fallbacks.
   - Ollama-specific code is removed from the pipeline; legacy configuration names remain temporary aliases.
   - The optional standard `reasoning_effort` is configurable and set to `none` for the 9B baseline to avoid generating only reasoning until `max_tokens` is exhausted.

2. Search reliability and candidate ranking
   - SearXNG `200 + empty results + unresponsive_engines` is treated as a transient outage and retried.
   - Expanded queries are kept sequential to avoid burst rate-limiting upstream search engines.
   - Duplicate URLs are aggregated across queries with deterministic reciprocal-rank-style scoring plus SearXNG engine/score signals.
   - Obvious search/tag/category/login pages are pruned before fetch.

3. Fetch qualification
   - Redirects are followed.
   - Final URL, status, content type, response bytes, raw characters, extracted characters, and failure reason are persisted.
   - PDF fetching is connected to the main pipeline.
   - HTML/unknown URLs returning `application/pdf` are rerouted to the PDF fetcher.
   - Fetches are bounded-concurrent; searches are not burst-concurrent.

4. Source pruning
   - Exact content duplicates are removed before Map.
   - Documents are ranked by retrieval evidence, lexical relevance, and content quality.
   - Map selection enforces a per-domain diversity cap.
   - `max_map_documents` is no longer a first-N slice of fetch order.

5. Summarization
   - Map output requests the Pydantic JSON schema when the backend supports it.
   - A global Reduce synthesizes validated Map summaries with explicit source IDs.
   - Unknown source IDs are rejected.
   - Reduce failure falls back to deterministic cited rendering instead of failing the run.

## Verified baseline

- Ruff check: PASS.
- Ruff format check: PASS after formatting.
- mypy: PASS.
- pytest: 57 passed.
- Live SearXNG/Web smoke test (`Linux kernel security latest`): search, ranking, fetch, selection, artifact persistence, and final rendering completed. One observed blocked source returned HTTP 403 and was preserved as an attributable fetch failure rather than collapsing the run.

## Next slices

1. Retrieval evaluation suite with labeled queries and Precision@k / nDCG / diversity / freshness / fetch-success metrics.
2. Evaluated query planning to replace the remaining rule-based expansion.
3. Source-quality scoring that distinguishes primary sources, reputable secondary reporting, aggregators, and low-value reposts by domain/task type.
4. Cluster/event grouping before global Reduce.
5. Qualified browser fallback for JS/WAF cases where policy and site behavior allow useful retrieval.
6. Media/source expansion after HTML/PDF reliability is measured.

## Acceptance principle

Do not claim a retrieval improvement from unit tests alone. Search changes must be measured against a fixed evaluation set and retain the raw candidate/ranking/fetch artifacts needed to explain regressions.
